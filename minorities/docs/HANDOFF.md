A bilingual (Arabic / English) reading site for Thaer Ahmad Salameh's
*نقض فقه الأقليات وبيان خطورته على الأقليات المسلمة*, built with the
new-book-engine (`~/Sites/new-book-engine`; read its `CLAUDE.md` and the first
section of `docs/LEARNINGS.md` before changing anything).

## What is in this folder

```
book.json        everything specific to the book
contents.json    chapters for the reader's contents panel (build_contents.py)
ar/N.txt         Arabic, page N = page N of the PDF (page 1 is the cover)
en/N.txt         English, the same lines as ar/N.txt
source/          the .docx and .pdf (git-ignored on purpose; the repo is public)
*.html, assets/  generated by build_site.py: never edit by hand
docs/HANDOFF.md  this file
```

Edit `ar/`, `en/`, `book.json`, `contents.json`; then from the engine folder:

```
python3 scripts/build_site.py  ../usul/minorities
python3 scripts/check_site.py  ../usul/minorities
```

## How the Arabic pages were made

The source is a Word `.docx` plus a PDF of it, from an archive.org download
(`20250709_20250709_0428`, which also has OCR, `_djvu.xml`, and a separate
English translation in a subfolder). The text comes from the `.docx`; the
page breaks come from the PDF.

- The PDF's own text layer is scrambled (doubled letters, Latin characters),
  so `split_docx_pages.py` could place only about 20 of 49 page starts. The
  engine now has `--ocr <book>_djvu.xml`, which lines the `.docx` up against
  the OCR of the page images, word by word:
  `python3 scripts/split_docx_pages.py <docx> --pdf <pdf> --ocr <djvu.xml> --out <site>`
- Page 1 is a picture (title, author, "1447 هـ - 2025 م"); its text was typed
  by hand in both languages.
- The OCR aligner is unreliable on tables. After the first split, every table
  page was checked against the PDF images and lines were moved between pages
  (8-12, 32, 46-49). Pages 36 and 40 hold flowchart pictures that are not in
  the text; the site does not show them.
- Page-end orphans were repaired by hand (a word that starts a page had been
  left on the page before: pages 9, 21, 28, 39).
- The Arabic contents on pages 47-49 gives printed page numbers; they equal
  the PDF page numbers, so `index.refs_fixed` is `true` and the entries were
  rewritten as `title ... N` so they become links.
- `find_garbled.py` reports 39 runs, all Latin acronyms and pasted URLs
  (FCNA, ISNA, `islamweb.net+15`), none Qur'anic. Nothing was changed.
- The one footnote is on page 32.

## Where the English comes from (the part to know)

The owner supplied an English `.docx`. It is **not a parallel translation**: it
is a rewrite with rebuilt tables, an added summary, author blurb and book list,
and its own contents numbering. So:

| pages | English source |
|---|---|
| 8-22, 25-30 | the engine's translator (gpt-4o-mini Batch API), then read and corrected by hand (verse references restored, mistranslations fixed) |
| 1, 44-47 end, 47-49 | written or fixed by hand (cover, end of conclusion, the contents list translated from the Arabic entries, the footnote on 32) |
| everything else | the supplied English, fitted to the Arabic pages by `scripts/align_english.py` (paragraph alignment by cost, cut by proportion at a page break) |

Consequences to keep in mind:

- `check_site.py` only counts lines, so it passes pages whose English is a
  loose fit. The supplied-English pages (2-7, 23-24, 31-46) read correctly in
  the places checked, but where a paragraph is cut across a page break the cut
  is an estimate, and in lists the English can sit one line out.
- The engine's output also drops some verse references and renders verses
  loosely; the pages were reviewed once, not word by word.
- Backups (in the engine's `work/`, not in this repo): `minorities-en-supplied`
  (all supplied English), `minorities-en-supplied-weak` (supplied English for
  the 21 re-translated pages), `minorities-weak` (the engine's raw output). Lines
  were later moved between pages 8-11, so these do not line up page for page.
- To redo a page with the engine: delete its `en/N.txt`, run
  `python3 scripts/translate_book_pages.py <site>`, review (CLAUDE.md,
  "Review the full translation"). Never use `small_pages` for index pages.

## Publishing, when asked

Follow the engine's `docs/DEPLOY.md`. Before the first push check
`git ls-files source` is empty (the Arabic and English source files must not
be in the public repo). Domain is undecided. After pushing run
`check_site.py <site> --live https://<domain-or-pages-url>`.
